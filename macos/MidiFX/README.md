# LogicでMerlai MIDI FXを使う

Apple Silicon Macのリポジトリのルートで実行します。ビルドにはCargo、Git、C++23対応のAppleツールチェーンが必要です。初回はAppleのAudioUnitSDKを固定コミットで取得します。

```sh
scripts/build-midi-fx.sh
mkdir -p ~/Library/Audio/Plug-Ins/Components
ditto dist/MerlaiFX.component ~/Library/Audio/Plug-Ins/Components/MerlaiFX.component
auval -v aumi MrFx Mrla
```

1. Logicを起動し、音源の入ったソフトウェア音源トラックの「MIDI FX」で「Audio Units」内のMerlaiを選びます。初回インストール中にLogicが開いていた場合はプロジェクトを保存して起動し直します。
2. Logic上部の黄色いサイクル範囲を、フレーズを含む2小節などに設定します。Merlai画面の「2 フレーズを取り込む」を押し、再生位置をサイクル先頭へ移して再生します。右端まで再生すると取り込みが完了します。途中は小節範囲・音数・進捗バー、完了後は青い原案ノートが表示されます。
3. 例として「後半だけ音数を半分に。最後の音は残して」を入力し、「変更内容を確認」を押します。青い原案の下にオレンジの修正案が表示されるので、位置と音数を目で比較できます。「修正案を聴く」で適用前に次の周回から試聴し、採用するときだけ「修正案を適用」を押します。「原案を聴く」で元へ戻して比較できます。
4. 再編集には「もう少し減らして」、直前の状態に戻るには「一手戻す」を使います。自由な文章への対応は限定的です。「休符を増やして」も発音の間引きとして扱います。
5. 採用時は送信元でMerlai直後を「MIDIをこのトラックに録音」の位置に指定し、別のソフトウェア音源トラックの内部MIDI入力で送信元を選択します。受け側を録音可能にして対象区間を録音し、ピアノロールで確認します。両トラックが発音するときは試聴用の出力を調整します。[Logicの内部MIDIルーティング](https://support.apple.com/guide/logicpro/lgcp1efa7c4d/mac)

取り込み上限は2048音です。再取り込みで履歴が消えるため、残す案は先に録音してください。MIDIのチャンネルメッセージを対象とし、SysEx・MIDI 2.0・プリセットの自動識別は対象外です。

## 別のMIDIトラックから生成する

1. 入力元トラックと生成先トラックの両方へMerlaiを挿します。
2. 入力元で分かりやすい「共有名」を入力し、サイクルを一周してフレーズを取り込みます。取り込み完了後の確定フレーズだけが共有されます。
3. 生成先の「入力元」一覧から共有名を選び、「入力を読み込む」を押します。入力元の範囲、音数、青いノートを確認します。
4. 元の音程とリズムを文章で直す場合は初期値の「編集: 元フレーズ」を使います。新しい役割を作る場合だけ「生成: ベース」「生成: コード」「生成: 対旋律」を選び、「候補を生成」を押します。オレンジの候補は「修正案を聴く」で適用前に試聴できます。
5. 採用する候補だけ「修正案を適用」で確定します。LogicのInternal MIDI Inでこのトラックを送信元として別のソフトウェア音源トラックへ録音できます。

## LLMで候補を生成する

モデル欄の「再検出」で、Codex CLI、Claude CLI、Ollama、LM Studioを探します。localhost上の別のOpenAI互換サーバーを使う場合はURLを入力して再検出します。ローカルサーバーは `/v1/models` と `/v1/chat/completions` に対応している必要があります。

「内蔵ルール」以外を選ぶと、候補生成時に指示、用途、範囲、Logicのテンポと拍子、入力元表示名、MIDIノートを構造化JSONで渡します。音声とLogicプロジェクトは渡しません。Codex CLIとClaude CLIはクラウド扱いのため毎回確認が表示されます。

画面の「使用中」には、生成へ実際に渡す入力元、種類、音数、音域、revisionが表示されます。入力元メニューを選び直しただけでは使用中のフレーズは変わらず、「入力を読み込む」で確定します。モデルの停止、不正な応答、未ログイン時は候補を作らずエラーを表示します。「候補を生成」で再試行するか、「内蔵で生成」を明示的に選べます。

共有は同じLogicプロセス内のMerlaiインスタンス間だけで行い、プロジェクトファイルや音声ファイルへ書き出しません。入力元を削除すると一覧からも消えます。現在は入力元トラック名をLogicから取得できないため、共有名は手動で設定します。

## ドラム音声を入力元にする

1. ドラムのオーディオトラックまたはソフトウェア音源トラックのAudio FXへ「Audio Units > Merlai > Audio Analyzer」を挿します。
2. Analyzerで共有名を設定し、Logicで解析するサイクルを指定します。「ドラムを解析」を押してサイクル先頭から右端まで再生します。Analyzerは原音を変更せず、オンセット位置、強度、音の明るさを収集します。
3. 生成先トラックのMerlai Generatorで、`[音声]`と表示される共有名を選びます。「入力を読み込む」「生成: ベース」「候補を生成」の順に押すと、ドラムのオンセット位置を保った候補を比較できます。

Audio Analyzerはオンセット、強度、音の明るさを扱い、低域・中域・高域のアタックをMIDIチャンネル10のキック（36）、スネア（38）、クローズドハイハット（42）相当へ分類します。ベース候補は検出したキック位置を優先するため、ハイハットの全打点でベースが鳴ることはありません。これは軽量な推定で、ドラム以外の音高・コードや和声の推定はまだ行いません。検出処理は固定サイズ状態を使い、オーディオスレッド上でメモリ確保、ロック、ファイルI/Oを行いません。

## 画面で状態を判断する

- 「待機中」のまま: 再生位置がサイクル先頭を通っていません。先頭へ移動して再生します。
- 進捗バーが動く: 正常に取り込み中です。右端まで止めずに再生します。
- 「取り込み失敗」: 対象範囲にノートがあるか、サイクルが有効かを確認します。
- Audio Analyzerが1音しか拾わない: Analyzerを挿したあとに再度「ドラムを解析」を押し、必ずサイクル先頭から一周させます。連続したハイハット上でも各アタックを再検出しますが、極端に潰したドラムバスより、MODO DRUMなど個別のドラム音源トラックへ挿す方が安定します。
- 青いノートだけ表示: 原案の取り込みは完了しています。指示を入力して「変更内容を確認」を押します。
- 青とオレンジを表示: まだプレビューです。採用する場合だけ「適用して修正案を聴く」を押します。
