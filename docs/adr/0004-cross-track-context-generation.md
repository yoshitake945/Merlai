# 0004　別トラックを文脈にしたMIDI生成

**状態**　提案。0003の単一トラック編集を残しながら段階的に追加する。

**追跡**　実装順序と受け入れ条件は[Issue #60](https://github.com/yoshitake945/Merlai/issues/60)で管理する。

**背景**　0003のMIDI FXは、挿した音源トラックへ到達するMIDIだけを取り込み、同じフレーズを推敲する。実際の作曲では、既存メロディーに対するベース、コード、対旋律や、ドラム音声のグルーヴに沿ったフレーズを、別の音源トラックへ生成したい。LogicのMIDI Processorは音声入力を持たず、別トラックの信号を暗黙に参照できないため、取得と生成を一つのプラグインへ閉じ込めない。

**判断**　Merlaiを次の責務へ分離する。

- **MIDI Listener** は入力元トラックのノート、サイクル範囲、テンポを取得し、正規化したフレーズを公開する。
- **Audio Analyzer** は入力元のAudio Effectとして音声を受け、オンセット、強度、テンポ上の位置を解析して公開する。音高・和声推定は後続機能とする。
- **Generator MIDI FX** は入力ソースと生成目的（ベース、コード、対旋律）を選び、候補を生成する。原案を青、生成案をオレンジで表示し、確認後だけMIDI出力へ反映する。
- **Standard MIDI Fileのドラッグ＆ドロップ** を正式な確定経路とし、Generatorで確定した候補をLogicの目的トラック・目的小節へ配置する。Internal MIDI Inはリアルタイム録音が必要な場合の互換経路として残す。MerlaiはLogicのプロジェクトやリージョンを直接書き換えない。
- **Generation Engine** は決定的なRustルールから開始し、ListenerとAnalyzerから独立した境界を持つ。AIモデルは同じ入出力契約の後段実装として追加する。

Generation Engineのモデル境界は`GenerationModel`とし、確定済みのノート列、対象範囲、生成目的を入力して、完成した候補を返す。モデルを設定しない場合、呼び出しが失敗した場合、または範囲外・不正な候補が返った場合は、既存の決定的ルールへフォールバックする。モデル候補にも、ノート数上限、有限な時刻、対象範囲、MIDI値の検証を適用する。

モデルプロバイダとの交換形式はバージョン付きJSONとする。要求には`instruction`、`purpose`、`span`、確定済みの`notes`を含め、応答は候補の`notes`だけを返す。`ModelTransport`はこのJSONバイト列の受け渡しだけを担当し、ネットワーク、ローカルプロセス、認証、モデル選択をGeneration Engineから分離する。JSONの通信・解析失敗も決定的ルールへのフォールバック対象とする。

```text
MIDIトラック ─ MIDI Listener ─┐
                              ├─ Context snapshot ─ Generation Engine
音声トラック ─ Audio Analyzer ┘                         │
                                                        ▼
                              Generator MIDI FX ─ MIDIファイル ─ Logicのドロップ先
```

プラグイン間で共有するのは、サイクル単位で確定した不変のスナップショットとする。Audio/MIDIのリアルタイムスレッドでは、メモリ確保、ロック、ファイルI/O、IPC、モデル推論を行わない。Generator画面は入力スナップショットを専用ワーカーへ渡し、完了した候補だけをメインスレッドでプレビューする。処理中に入力が変わった場合は古い結果を破棄し、完成した候補だけをサイクル境界で交換する。接続先を明示して、別プロジェクトや無関係なプラグインインスタンスのデータを混ぜない。

**導入順序**

1. 別のMIDIトラックを入力元として選択する。
2. ベース、コード、対旋律から生成目的を選択する。
3. 原案と生成案を現在の青・オレンジ表示で比較する。
4. 確定候補をLogicの生成先トラック・目的小節へドラッグして配置する。
5. Audio Analyzerを追加し、ドラム音声のオンセットと強度を文脈に使う。
6. AIモデルをGeneration Engineへ接続し、自由文の作曲指示を扱う。

**段階ごとの完了条件**

- MIDI段階は、異なるトラックの2小節を取り込み、3種類の目的ごとに候補を生成し、Logic上で選択した生成先・位置へMIDIリージョンとして配置できること。
- 比較段階は、入力元、対象小節、音数、生成目的、原案、候補をプラグイン画面で識別でき、適用前には出力を変更しないこと。
- Audio段階は、ドラム音声のオンセットをサイクル上へ表示し、その位置を使ったMIDI候補を生成できること。原音は変更しないこと。
- AI段階は、モデルが未導入または失敗しても決定的な生成と再生を継続でき、モデル処理がリアルタイムスレッドを停止しないこと。

**帰結**　確定候補はテンポイベントを含まないFormat 0の標準MIDIファイルとして書き出す。拍単位のノート位置と先頭休符を保持し、Logic上のドロップ先がリージョンのトラックと開始位置になる。Audio Unitの公開ホスト情報にはプロジェクトのトラック一覧やリージョン作成操作がないため、アクセシビリティによるLogic画面の自動操作は正式経路にしない。音源やチャンネルストリップをMerlaiが再現せず、ユーザーが選んだ音源をそのまま試聴できる。音声解析とAIは後から交換可能で、リアルタイムスレッドではファイルI/Oを行わない。

**対象外**　初期段階では、Logicのプロジェクトファイルへの直接書き込み、プラグイン音色の自動選択、ポリフォニック音声の完全な採譜、生成案の無確認適用を行わない。
